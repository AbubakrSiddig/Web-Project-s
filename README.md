# منظومة بوكر فارما لإدارة الأعمال وتوزيع الأدوية (Poker Pharma Business Management System)
### الإصدار: MVP v0.1 | شركة بوكر فارما للتجارة والاستثمار المحدودة — جمهورية السودان

---

## 1. نبذة عن المنظومة والهدف (Executive Overview)
منظومة **بوكر فارما** هي حل رقمي متكامل مصمم خصيصاً لشركات ومستودعات توزيع الأدوية والمستلزمات الطبية. تهدف المنظومة إلى إدارة سلسلة الإمداد الدوائي بالكامل، بدءاً من توريد الأدوية من المصانع والموردين، وتخزينها وإدارتها عبر المستودعات المتعددة وغرف التبريد وسلاسل الإمداد الباردة، وصولاً إلى بيعها وتوزيعها على الصيدليات والمراكز الطبية مع الرقابة الصارمة على الصلاحيات وحسابات العملاء والخزائن النقدية.

---

## 2. الهيكلية التقنية (Architecture & Technical Stack)

### النواة الخلفية (Backend)
- **لغة البرمجة**: Native PHP (متوافقة بالكامل مع PHP 7.1+ وحتى أحدث إصدارات PHP 8.x دون أي تعارض).
- **النمط المعماري**: MVC + Services Layer + Repository Pattern عبر Interfaces مجردة تعزل استعلامات SQL تماماً لتسهيل استبدال قاعدة البيانات لاحقاً بـ Realm DB.
- **قاعدة البيانات**: MySQL 8.x / MariaDB 10.x (`poker_pharma`)، محرك InnoDB، ترميز `utf8mb4_unicode_ci`، مكونة من 31 جدولاً موحداً مع علاقات تكامل مرجعي صارمة وفهارس أداء على الحقول المتكررة.
- **الأمان والمصادقة**: تشفير كلمات المرور عبر `password_hash(BCRYPT)`، وتوليد رموز توثيق مشفرة `HS256 JWT`، ومصفوفة صلاحيات تفصيلية (RBAC) مدعومة بـ Middleware للحماية على مستوى كل مسار (Route).
- **سجل التدقيق الأمني (Audit Trail)**: تسجيل فوري لكافة العمليات الحساسة (إنشاء، تعديل، إلغاء، تسوية) في جدول `audit_logs` متضمناً الفروقات القديمة والجديدة بتنسيق JSON، ومعرف المستخدم، وعنوان IP.

### الواجهة الأمامية (Frontend)
- **التقنيات**: HTML5، CSS3، Bootstrap 5 RTL، خط Cairo العربي، مكتبة أيقونات FontAwesome 6، ومخططات بيانية تفاعلية عبر Chart.js.
- **التصميم المعماري**: واجهة أحادية الصفحة (SPA) مفصولة تماماً عن لغة الخادم، تتواصل مع الـ Backend عبر RESTful JSON API باستخدام Fetch API الموحد.
- **مرونة التشغيل**: ملف تهيئة مركزي موحد (`public/api-config.js`) يكتشف تلقائياً بيئة التشغيل سواء عبر المتصفح أو داخل تطبيق سطح المكتب Electron دون الحاجة لتعديل سطر كود واحد.

### تطبيق سطح المكتب (Desktop Client)
- **الإطار**: Electron Framework.
- **الملفات**: `electron/main.js`، `electron/preload.js`، و `electron/package.json`.
- **المزايا**: تشغيل كتطبيق Windows سطح مكتب، فحص تلقائي لسلامة خادم PHP، قوائم عربية أصلية، ودعم الطباعة الحرارية المباشرة لفواتير نقاط البيع (80mm / 57mm).

## 3. القواعد والمعايير الدوائية المطبقة (Pharma Business Rules)

1. **المنع الصارم لصرف الأدوية المنتهية (Zero Tolerance for Expired Drugs)**:
   - يمنع النظام منعاً باتاً إصدار أي فاتورة بيع تحتوي على دواء منتهي الصلاحية (`expiry_date <= CURRENT_DATE()`).

2. **محرك الصرف الذكي (FEFO / FIFO Dispatch Engine)**:
   - السياسة الافتراضية المعتمدة هي **FEFO** (الأقرب انتهاءً يُصرف أولاً لحماية المنشأة من رواكد الأدوية).
   - إمكانية التبديل إلى **FIFO** (الأقدم وروداً يُصرف أولاً) للمستلزمات الطبية.

3. **التحكم في سقف الائتمان للصيدليات (Credit Limit Enforcement)**:
   - يتم تحديد سقف ائتماني لكل صيدلية. إذا تجاوزت الفاتورة الآجلة السقف المسموح به، يتم إيقاف العملية تلقائياً ما لم يتدخل مدير النظام بصلاحية التجاوز المعتمدة (`sales.override_credit`).

4. **حماية الحد الأدنى لسعر البيع (Minimum Selling Price)**:
   - يمنع موظفي المبيعات من تقديم خصومات تؤدي إلى بيع الصنف بأقل من سعر التكلفة أو الحد الأدنى المعتمد.

5. **توجيه المرتجعات التالفة للحجر الصحي (Quarantine Routing)**:
   - عند استلام مرتجع تالف أو منتهي الصلاحية من عميل، يتم توجيهه تلقائياً إلى مخزن الحجر الصحي (`Quarantine Warehouse`) لمنع اختلاطه بالبضاعة الصالحة للبيع.

6. **سلامة الأرصدة والقيود المحاسبية (Zero Data-Loss Accounting)**:
   - كل حركة دخول أو خروج تسجل في سجل `stock_transactions` غير القابل للتعديل.
   - كشوفات الحسابات (`customer_transactions` و `supplier_transactions`) تُسجل بدقة وفق مبدأ القيد المزدوج.

## 4. متطلبات التشغيل والتثبيت السريع (Setup & Installation)

### المتطلبات الأساسية
- خادم محلي مثل **XAMPP** أو **WampServer** (PHP 7.1+ أو PHP 8.x، مع تفعيل امتدادات `pdo_mysql`, `mbstring`, `openssl`, `json`).
- خادم **MySQL 8.x** أو **MariaDB 10.x**.
- منصة **Node.js** (فقط في حال الرغبة في تشغيل أو بناء تطبيق سطح المكتب Electron).

### خطوات تثبيت قاعدة البيانات
1. تشغيل خادم MySQL عبر لوحة تحكم XAMPP.
2. تشغيل سكربت الهجرة لإنشاء الـ 31 جدولاً وزرع البيانات الأولية:
   ```bash
   php database/migrate.php
   ```
   أو استيراد ملف `database/schema.sql` ثم ملف `database/seeds.sql` عبر phpMyAdmin.

### تشغيل خادم الويب المحلي
من المجلد الرئيسي للمشروع، قم بتشغيل الخادم المدمج:
```bash
php -S 127.0.0.1:8000 -t public
```
افتح المتصفح وتوجه إلى: `http://127.0.0.1:8000`

### تشغيل تطبيق سطح المكتب (Electron)
```bash
cd electron
npm install
npm start
```

## 5. الحسابات الافتراضية وصلاحيات الدخول (Default Accounts)

كلمة المرور الموحدة لكافة الحسابات الافتراضية هي: `Admin@123456`

| اسم المستخدم (Username) | الاسم الكامل | الدور الوظيفي (Role) | الصلاحيات الرئيسية |
| :--- | :--- | :--- | :--- |
| **`admin`** | مدير النظام العام | مدير النظام (System Admin) | كافة صلاحيات المنظومة (38 صلاحية) |
| **`manager`** | د. مصطفى البشير | مدير الفرع / المبيعات (Branch Manager) | إدارة المبيعات، اعتماد الائتمان، التقارير |
| **`pharmacist`** | د. سارة عثمان | صيدلي مسؤول (Pharmacist) | إدخال وتعديل الأصناف، فحص الصلاحيات |
| **`cashier`** | أحمد خالد | كاشير نقاط البيع (Cashier) | إصدار فواتير المبيعات وسندات القبض |
| **`accountant`** | محمد الأمين | محاسب مالي (Accountant) | الخزائن، البنوك، السندات، تقارير P&L |
| **`keeper`** | عثمان فضل | أمين مستودع (Warehouse Keeper) | استلام البضاعة، التحويلات، الجرد |
